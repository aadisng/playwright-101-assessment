# Playwright 101 assessment

TypeScript + Playwright Test automation for the TestMu AI Selenium Playground.

## Setup

Use Node.js 22 or later.

```sh
npm ci
npx playwright install chromium firefox
npm run typecheck
npm run test:local
npm run report
```

The lockfile pins the installed dependencies. The project was created with Playwright 1.64.1, the latest npm release available during implementation.

## Scenarios

| Scenario | Assertions |
| --- | --- |
| Simple Form Demo | Navigate from playground, verify URL, enter a string variable, assert exact echoed message |
| Drag & Drop Sliders | Identify the default-15 slider, drag its native thumb toward 95, correct native pixel rounding with arrow keys if necessary, assert input and visible output are 95 |
| Input Form Submit | Submit empty form, assert native required-field error and blocked submission, fill every field, select United States by visible label, assert exact success message |

The suite uses role/name locators, placeholder locators, and CSS ID/attribute locators. Tests use isolated browser contexts and auto-waiting assertions; there are no fixed sleeps or forced passes. The simple form and submission tests click an input to start the site's deferred client initialization, then wait until the playground has attached its jQuery event handlers. Server-rendered controls can become visible before those handlers are ready. The wait observes the element event cache and does not modify application behavior.

### Required-field wording

The assessment describes the error as “Please fill in the fields”. The current site uses HTML5 `required` validation, rather than a custom message with that wording. Live Chromium and Firefox both return `Please fill out this field.` in English. The test asserts that actual message, `validity.valueMissing`, invalid state, focus on the first field, and absence of success. It does not modify the application to manufacture the assessment wording. The native message is attached to the report.

## Run on TestMu AI

1. In the Automation Dashboard, open **Access Key** and copy the automation username and access key. The account login password is not the automation access key.
2. Copy `.env.example` to `.env` and populate `LT_USERNAME` and `LT_ACCESS_KEY` locally.
3. Ensure the account has automation minutes and at least two parallel sessions.
4. Run:

```sh
npm run test:cloud
npm run sessions
```

On Windows PowerShell, set `$env:TEST_TARGET='cloud'` then run `npx playwright test` instead of the POSIX `test:cloud` script.

Cloud projects:

- Chrome latest / Windows 10
- Playwright Firefox latest / macOS Sonoma

Two workers are enabled, with one worker per cloud project so both browser/OS combinations can execute concurrently. Each test creates a separate cloud session: six sessions for the complete matrix. No local browser is launched for cloud runs.

Every session enables `network`, `video`, `visual` (command screenshots), and `console` in `LT:Options`. Cloud video is recorded by the provider; native Playwright video is enabled only for local runs because some grid images lack the ffmpeg binary. Session status is sent to TestMu. Only session identifiers and dashboard URLs are retained from cloud metadata. Connection errors are redacted so credentials embedded in the WebSocket URL are not printed.

The provider still uses the `cdp.lambdatest.com` endpoint under the TestMu AI brand. See the official [Playwright setup](https://www.testmuai.com/support/docs/playwright-testing/) and [diagnostic capabilities](https://www.testmuai.com/support/docs/playwright-test-execution-setup/).

## Evidence and submission

- `playwright-report/index.html`: HTML report with screenshots, console messages, traces, HAR files, and videos.
- `test-results/results.json`: machine-readable results and per-test session attachments.
- `test-results/cloud-sessions.json`: generated by `npm run sessions` after a cloud run; contains actual session IDs for submission.
- TestMu Automation Dashboard: cloud video, command screenshots, network and console logs.

Submit the repository URL and the six actual cloud test session IDs in the exam portal. Local results do not satisfy the cloud execution requirement. This project does not invent session IDs or mark unexecuted cloud tests as passed.

The assessment asks for a private repository shared with its administrator. This workspace was prepared for public publishing at the candidate's explicit request; reconcile the visibility requirement with the assessment before submitting. Account credentials, `.env`, reports, and runtime artifacts are excluded from Git.

## GitHub Actions

Pushes and pull requests run the local Chromium/Firefox matrix on Ubuntu. A manual workflow dispatch with **cloud** enabled runs the cloud matrix using repository secrets `LT_USERNAME` and `LT_ACCESS_KEY`. Cloud minutes are used only for manual cloud dispatches. Workflow artifacts retain the reports and diagnostics for seven days.
